# Huggingface 캐시 관리

딥러닝 모델을 HuggingFace Hub에서 받아 쓸 때 (Depth Anything V2, Stable Video Diffusion, DepthCrafter, StereoCrafter 등), **모델 캐시를 어디에 두고 어떻게 오프라인으로 쓸지** 정리.

## 기본 캐시 위치

```
~/.cache/huggingface/
├── hub/          # 모델 가중치, config, tokenizer (가장 큼)
├── datasets/     # datasets 라이브러리 캐시
└── ...
```

리눅스/WSL2 모두 `~/.cache/huggingface/` 기본. 용량은 모델 하나당 보통 수백 MB ~ 수 GB (예: DepthAnythingV2-Large = 1.34GB, SVD = 수 GB).

## 가장 자주 쓰는 환경변수

| 변수 | 역할 |
|---|---|
| `HF_HUB_OFFLINE=1` | HuggingFace Hub **네트워크 호출 완전 차단**, 캐시만 사용. 캐시에 없으면 바로 에러. |
| `TRANSFORMERS_OFFLINE=1` | `transformers` 라이브러리 전용 오프라인 모드 (동일 효과) |
| `HF_HOME=/custom/path` | 캐시 루트 위치 변경 (기본 `~/.cache/huggingface`) |
| `HF_HUB_CACHE=/custom/path` | hub 캐시만 별도 위치 지정 (`HF_HOME`보다 우선) |
| `HF_TOKEN=hf_xxx...` | private 모델/repo 접근용 토큰 |
| `HF_HUB_DISABLE_TELEMETRY=1` | 텔레메트리 차단 |
| `HF_HUB_ENABLE_HF_TRANSFER=1` | `hf_transfer` 사용해서 다운로드 가속 (`pip install hf_transfer` 필요) |

## 오프라인 모드 사용 패턴

### 1) 한 번 다운로드 → 이후 오프라인

가장 흔한 패턴. 연구 환경에서 매 실행마다 HF 서버 ping 보내는 게 느리거나, 네트워크 불안한 환경에서 유용.

```bash
# 최초 1회: 네트워크 연결된 상태에서 모델 로드 (자동 다운로드)
python -c "from transformers import pipeline; pipeline('depth-estimation', model='depth-anything/Depth-Anything-V2-Large-hf')"

# 이후: 오프라인 강제
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1

# 이제 매 실행마다 서버 ping 없이 캐시에서 바로 로드
bash run_3d_photo.sh ./images
```

### 2) 인터넷 없는 환경 (사내 슈퍼컴)

평소 쓰는 환경(WSL2, 가정 PC 등)에서 모델을 받아놓고 복사 이전.

```bash
# 로컬에서: 모델 다운로드
python -c "from transformers import pipeline; pipeline('depth-estimation', model='depth-anything/Depth-Anything-V2-Large-hf')"

# 캐시를 슈퍼컴에 rsync
rsync -av --progress ~/.cache/huggingface/ user@supercomputer:~/.cache/huggingface/

# 슈퍼컴 환경에서 오프라인 플래그
export HF_HUB_OFFLINE=1
```

### 3) 특정 모델만 수동으로 받기 (`huggingface-cli`)

```bash
pip install -U "huggingface_hub[cli]"

# 전체 repo를 다운로드 (snapshot)
huggingface-cli download depth-anything/Depth-Anything-V2-Large-hf \
    --local-dir ~/models/Depth-Anything-V2-Large-hf \
    --local-dir-use-symlinks False

# 특정 파일만
huggingface-cli download tencent/DepthCrafter \
    unet/diffusion_pytorch_model.safetensors \
    --local-dir ~/models/DepthCrafter
```

`--local-dir-use-symlinks False`는 실제 파일을 복사 (symlink 아님) → 그 폴더만 옮기면 다른 머신에서 바로 사용 가능.

## 환경변수 영구 설정

### 방법 A: conda env별 (권장)

특정 환경에서만 적용. 다른 프로젝트에 영향 없음.

```bash
conda activate stereocrafter

mkdir -p $CONDA_PREFIX/etc/conda/activate.d
cat > $CONDA_PREFIX/etc/conda/activate.d/hf_offline.sh <<'EOF'
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
# 캐시 위치를 바꾸고 싶다면:
# export HF_HOME=/ssd_data/hf_cache
EOF

# 비활성화 시 원상복구하고 싶다면
mkdir -p $CONDA_PREFIX/etc/conda/deactivate.d
cat > $CONDA_PREFIX/etc/conda/deactivate.d/hf_offline.sh <<'EOF'
unset HF_HUB_OFFLINE
unset TRANSFORMERS_OFFLINE
EOF
```

→ 더 자세한 conda activate.d 패턴은 [[conda/환경-관리]] 참조.

### 방법 B: venv / uv 프로젝트별 (권장)

슈퍼컴 같은 conda 없는 환경, 또는 uv 기반 프로젝트에서 사용.

#### B-1. `.venv/bin/activate` 직접 수정

가장 간단한 방법. venv가 활성화될 때 자동 export:

```bash
# 프로젝트 루트에서
cat >> .venv/bin/activate <<'EOF'

# Huggingface offline
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
# 캐시 위치를 바꾸고 싶다면:
# export HF_HOME=/ssd_data/hf_cache
EOF
```

비활성화 시 unset하고 싶으면 `deactivate` 함수를 덮어써야 하는데 번거로우니, 필요시 쉘에서 직접 `unset HF_HUB_OFFLINE`.

**주의**: `uv venv` / `uv sync`가 `.venv`를 재생성하면 이 수정이 날아갑니다. 자주 재생성되는 프로젝트라면 B-2 또는 B-3 추천.

#### B-2. 프로젝트 루트의 `env.sh` 스크립트

venv 재생성에 강건한 방법. 프로젝트 루트에 별도 파일:

```bash
# project_root/env.sh
source .venv/bin/activate
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

이후 매번 `source env.sh`로 진입. 팀 공유 시에도 명시적이라 유리 (`.gitignore`에 올리지 않고 commit 해도 됨).

#### B-3. direnv (자동 로드, 가장 매끄러움)

[direnv](https://direnv.net/) 설치되어 있다면 프로젝트 루트에 `.envrc`:

```bash
# project_root/.envrc
source .venv/bin/activate
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

처음 한 번 `direnv allow` 하면, 이후에는 프로젝트 디렉토리에 `cd` 할 때마다 자동 로드되고 빠져나가면 자동 unset. 수동 activate 필요 없음. `.envrc`는 보통 `.gitignore` 처리 (개인 설정).

### 방법 C: `~/.bashrc` (전역)

모든 conda env, 모든 프로젝트에서 HF 오프라인. 단, 새 모델 받을 일이 생기면 매번 `unset HF_HUB_OFFLINE` 해야 함.

```bash
echo 'export HF_HUB_OFFLINE=1' >> ~/.bashrc
echo 'export TRANSFORMERS_OFFLINE=1' >> ~/.bashrc
source ~/.bashrc
```

## 캐시 용량 관리

### 현재 용량 확인

```bash
du -sh ~/.cache/huggingface/
du -sh ~/.cache/huggingface/hub/*     # 모델별 용량
```

### `huggingface-cli scan-cache`

모델별 크기, 마지막 사용 시각 등 상세 조회.

```bash
pip install -U "huggingface_hub[cli]"
huggingface-cli scan-cache
```

출력 예시:
```
REPO ID                                          SIZE ON DISK    LAST_ACCESSED
depth-anything/Depth-Anything-V2-Large-hf        1.3G            2 days ago
stabilityai/stable-video-diffusion-img2vid-xt    9.6G            1 week ago
```

### 오래된 캐시 정리

```bash
huggingface-cli delete-cache
```

대화형 TUI로 선택 가능.

## 트러블슈팅

### "OSError: We couldn't connect to 'https://huggingface.co' ..."

`HF_HUB_OFFLINE=1` set된 상태인데 캐시에 해당 모델이 없을 때. 해결:
```bash
unset HF_HUB_OFFLINE
unset TRANSFORMERS_OFFLINE
# 다시 실행하면 다운로드
```

### "403 Forbidden" / "gated repo"

Gated model (예: Llama)에 접근하려면 HF 계정으로 웹에서 수락 후 토큰 필요.
```bash
export HF_TOKEN=hf_xxx...
# 또는 인터랙티브 로그인
huggingface-cli login
```

### 디스크 공간 부족 (`~` 파티션 작음)

WSL2 / 사내 서버에서 홈이 작을 때 자주 발생. `HF_HOME`을 큰 디스크로 재지정:
```bash
export HF_HOME=/ssd_data/seungho/hf_cache
# 이후 모든 HF 라이브러리가 여기에 저장/조회
```

기존 캐시 옮기려면 먼저 rsync:
```bash
mkdir -p /ssd_data/seungho/hf_cache
rsync -av ~/.cache/huggingface/ /ssd_data/seungho/hf_cache/
rm -rf ~/.cache/huggingface
```

### 다운로드 속도 가속

큰 모델 받을 때 (SVD 9GB 등):
```bash
pip install hf_transfer
export HF_HUB_ENABLE_HF_TRANSFER=1
python -c "from transformers import ..."  # 평소보다 빠르게 다운로드
```

## 실전 시나리오 요약

| 상황 | 설정 |
|---|---|
| WSL2에서 개발, 같은 모델 반복 사용 | `HF_HUB_OFFLINE=1` conda activate.d에 |
| 슈퍼컴 (인터넷 없음) | 로컬에서 rsync로 캐시 이전 + `HF_HUB_OFFLINE=1` |
| 홈 디렉토리 용량 부족 | `HF_HOME=/big_disk/hf_cache` |
| 새 모델 받을 때 | `unset HF_HUB_OFFLINE` 후 실행, 다시 export |
| 큰 모델 (SVD 등) 받을 때 | `HF_HUB_ENABLE_HF_TRANSFER=1` + `pip install hf_transfer` |
| Private/gated 모델 | `HF_TOKEN=hf_...` 또는 `huggingface-cli login` |
