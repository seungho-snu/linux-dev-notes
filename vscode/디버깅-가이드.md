# VS Code 디버깅 완전 가이드

## 1단계: 사전 준비

### 필수 확장(Extension) 설치

VS Code 좌측 Extensions 탭 (`Ctrl+Shift+X`)에서 설치:

```
Python                    — Microsoft (Python 언어 지원 + 디버거)
Pylance                   — Microsoft (자동완성, 타입 체크)
```

Python 확장을 설치하면 `debugpy` (Python 디버거)가 자동으로 포함된다.

### Python 인터프리터 선택

```
Ctrl+Shift+P → "Python: Select Interpreter" → conda 환경 선택
```

conda 환경이 목록에 안 보이면 직접 경로 입력:

```
~/miniconda3/envs/sharp/bin/python
```

> 💡 **확인**: VS Code 하단 상태바에 선택된 Python 환경이 표시된다. 잘못된 환경이면 디버깅 시 import 에러 발생.

### 프로젝트 폴더 열기

```
File → Open Folder → 프로젝트 루트 폴더 선택
```

`launch.json`의 `${workspaceFolder}`가 이 폴더를 가리킨다. 반드시 프로젝트 루트를 열어야 한다.

## 2단계: launch.json 생성

### 생성 방법

```
좌측 Run and Debug 탭 (Ctrl+Shift+D) → "create a launch.json file" 클릭 → Python Debugger 선택
```

또는 직접 `.vscode/launch.json` 파일을 만들어도 된다.

### 기본 구조

```jsonc
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "디버그 설정 이름",      // Run and Debug 드롭다운에 표시됨
            "type": "debugpy",              // Python 디버거
            "request": "launch",            // 새 프로세스 시작 (vs "attach": 실행 중 프로세스에 연결)
            "program": "${workspaceFolder}/main.py",
            "args": [],
            "console": "integratedTerminal"
        }
    ]
}
```

## 3단계: launch.json 옵션 상세

### 핵심 옵션

```jsonc
{
    // ── 기본 ──
    "name": "표시 이름",
    "type": "debugpy",                      // Python 디버거 (구버전은 "python"이었음)
    "request": "launch",                    // "launch" = 새로 실행, "attach" = 기존 프로세스에 연결

    // ── 실행 대상 ──
    "program": "${workspaceFolder}/train.py",  // 실행할 파이썬 파일
    "module": "torch.distributed.launch",      // program 대신 모듈로 실행 (python -m 방식)
    "args": ["--lr", "0.001", "--epochs", "10"],  // 명령줄 인자 (문자열 배열)

    // ── 환경 ──
    "cwd": "${workspaceFolder}",            // 작업 디렉토리
    "env": {                                // 환경변수 추가/덮어쓰기
        "CUDA_VISIBLE_DEVICES": "0",
        "PYTHONPATH": "${workspaceFolder}/src"
    },
    "envFile": "${workspaceFolder}/.env",   // .env 파일에서 환경변수 로드

    // ── Python 설정 ──
    "python": "/home/user/miniconda3/envs/sharp/bin/python",  // 특정 Python 경로 지정
    "console": "integratedTerminal",        // "integratedTerminal" | "externalTerminal" | "internalConsole"

    // ── 디버깅 범위 ──
    "justMyCode": false,                    // false → 라이브러리 코드 내부까지 디버깅 가능
    "stopOnEntry": true,                    // 프로그램 첫 줄에서 자동 중단

    // ── 사전 작업 ──
    "preLaunchTask": "build",               // 디버깅 전에 tasks.json의 task 실행
}
```

### justMyCode 옵션 상세

```jsonc
// true (기본값): 내 코드만 디버깅 — site-packages 안의 코드는 브레이크포인트 무시
"justMyCode": true

// false: 모든 코드 디버깅 — pip 설치된 라이브러리, editable install 코드 내부까지 진입
// ★ pip install -e . 로 설치한 패키지 디버깅 시 반드시 false!
"justMyCode": false
```

> 💡 SHARP처럼 `pip install -e .`로 editable install한 패키지의 내부 코드를 디버깅하려면 **반드시 `justMyCode: false`**.

### console 옵션 비교

| 값 | 설명 | 용도 |
|---|---|---|
| `integratedTerminal` | VS Code 내장 터미널 | 대부분의 경우 (stdin 입력 가능) |
| `externalTerminal` | 별도 터미널 창 | GUI 프로그램, 터미널 기능 필요 시 |
| `internalConsole` | 디버그 콘솔 | 출력만 볼 때 (stdin 불가) |

### 변수 치환 (Variables)

launch.json에서 사용 가능한 변수:

```jsonc
"${workspaceFolder}"      // 프로젝트 루트 (열린 폴더)
"${file}"                 // 현재 열린 파일
"${fileBasename}"         // 현재 파일명 (경로 없이)
"${fileDirname}"          // 현재 파일의 폴더
"${env:HOME}"             // 환경변수 참조
"${input:inputName}"      // 실행 시 사용자에게 입력 받기 (inputs 섹션 필요)
```

### 예시 3) click CLI 도구 디버깅 (래퍼 방식)

click 기반 CLI는 직접 `program`으로 지정하면 디버거가 진입점을 못 잡는다.
래퍼 스크립트를 만들어서 우회:

**debug_launch.py:**
```python
"""VS Code 디버깅용 래퍼. click CLI를 디버거에서 실행."""
from my_tool.cli import main_cli

if __name__ == "__main__":
    main_cli()
```

**launch.json:**
```jsonc
{
    "name": "CLI: predict",
    "type": "debugpy",
    "request": "launch",
    "program": "${workspaceFolder}/debug_launch.py",
    "args": [
        "predict",                          // click 서브커맨드
        "-i", "./input/images/",
        "-o", "./results/",
        "--render"
    ],
    "console": "integratedTerminal",
    "justMyCode": false
}
```

### 예시 4) shell 스크립트 안의 Python을 디버깅

`run.sh` 안에 `python train.py --lr 0.001 ...`이 있으면, sh를 디버깅하는 게 아니라 **안의 Python 명령을 launch.json으로 옮기는 게 정석**:

```bash
# run.sh 내용:
CUDA_VISIBLE_DEVICES=0,1 python -m torch.distributed.launch \
    --nproc_per_node=2 train.py --lr 0.001 --batch-size 64
```

→ launch.json으로 변환:

```jsonc
{
    "name": "Distributed Train",
    "type": "debugpy",
    "request": "launch",
    "module": "torch.distributed.launch",   // python -m 방식
    "args": [
        "--nproc_per_node=2",
        "train.py",
        "--lr", "0.001",
        "--batch-size", "64"
    ],
    "env": {
        "CUDA_VISIBLE_DEVICES": "0,1"
    },
    "console": "integratedTerminal",
    "justMyCode": false
}
```

> ⚠️ 단, 분산 학습 디버깅은 한 프로세스만 디버거에 붙으므로 rank 0만 브레이크포인트가 걸린다.

### 예시 8) 원격 서버 Attach (debugpy)

서버에서 학습 실행 후, VS Code에서 원격 연결:

**서버 측 코드 삽입:**

**launch.json:**
```jsonc

    "name": "Attach: Remote Server",
    "type": "debugpy",
    "request": "attach",

        "host": "gpu-server.company.com",   // 서버 주소

        {
            "localRoot": "${workspaceFolder}",

    ],
    "justMyCode": false
}
```

## 5단계: 디버깅 실행 & 조작

### 브레이크포인트 설정

```
코드 좌측 줄 번호 옆 클릭 → 빨간 점 표시 = 브레이크포인트
```

브레이크포인트 종류:

| 종류 | 설정 방법 | 설명 |
|------|----------|------|
| 일반 | 줄 번호 클릭 | 해당 줄에서 멈춤 |
| 조건부 | 우클릭 → Conditional | `i == 100` 같은 조건이 참일 때만 멈춤 |
| 히트카운트 | 우클릭 → Hit Count | N번째 도달 시 멈춤 (루프 디버깅) |
| 로그포인트 | 우클릭 → Logpoint | 멈추지 않고 메시지 출력 (`{variable}` 사용) |
| 예외 | Breakpoints 패널 | Raised/Uncaught Exceptions 체크 |

### 실행 & 단축키

```
F5              — 디버깅 시작 (launch.json 설정으로)
Ctrl+Shift+D    — Run and Debug 패널 열기
```

상단 드롭다운에서 원하는 설정 선택 후 F5.

### 디버깅 중 조작 단축키

```
F5              — Continue (다음 브레이크포인트까지 실행)
F10             — Step Over (현재 줄 실행, 함수 안으로 안 들어감)
F11             — Step Into (함수 안으로 진입)
Shift+F11       — Step Out (현재 함수 밖으로 나감)
Ctrl+Shift+F5   — 재시작
Shift+F5        — 디버깅 중지
```

> 💡 **F10 vs F11**: `model.forward(x)` 줄에서 F10 누르면 결과만 받고, F11 누르면 forward 내부로 들어간다.

### 디버그 콘솔 활용

디버깅 중 하단 "Debug Console"에서 Python 코드를 직접 실행할 수 있다:

```python
# 변수 값 확인
tensor.shape
model.parameters().__next__().device

# 중간에 값 변경
lr = 0.0001

# 복잡한 확인
import torch
torch.cuda.memory_allocated() / 1024**3  # GPU 메모리 (GB)
```

### VARIABLES 패널

디버깅 중 좌측에 현재 스코프의 변수들이 표시된다:
- **Locals** — 현재 함수의 지역 변수
- **Globals** — 전역 변수
- Tensor 같은 큰 객체는 펼쳐서 shape, dtype, device 등 확인 가능

### WATCH 패널

감시할 표현식을 등록하면 매 스텝마다 값이 갱신된다:

```
loss.item()
optimizer.param_groups[0]['lr']
x.shape
torch.cuda.memory_allocated()
```

### CALL STACK 패널

현재 함수 호출 스택을 보여준다. 클릭하면 해당 프레임으로 이동. `justMyCode: false`일 때 라이브러리 내부 스택도 볼 수 있다.

## 자주 겪는 문제 & 해결

### "No module named ..." 에러

→ VS Code 하단에서 Python 인터프리터가 올바른 conda 환경인지 확인.
→ launch.json에 `"python"` 경로를 명시적으로 지정.

### editable install 코드에 브레이크포인트가 안 걸림

→ `"justMyCode": false` 설정 확인.
→ `pip install -e .`로 설치한 패키지는 site-packages가 아닌 소스 폴더를 직접 참조하므로 `justMyCode`가 false여야 진입 가능.

### click CLI 디버깅 시 "Error: Missing command" 에러

→ click은 `sys.argv`를 파싱하므로 직접 실행이 안 될 수 있다. `debug_launch.py` 래퍼를 만들어서 `main_cli()`를 직접 호출. (위 예시 3 참조)

### 디버깅이 느리다

→ `"justMyCode": true`로 변경 (라이브러리 코드 추적 안 함).
→ 불필요한 브레이크포인트 제거.
→ 조건부 브레이크포인트 활용 (루프 전체가 아닌 특정 조건에서만 멈춤).

### GPU 메모리가 디버깅 시 더 많이 소모됨

→ 디버거가 변수 참조를 유지하므로 GC가 안 되는 경우 있음.
→ `del tensor` + `torch.cuda.empty_cache()` 디버그 콘솔에서 수동 실행.

### WSL 환경에서 VS Code 터미널 단축키 충돌

VS Code가 `Ctrl+K`, `Ctrl+U` 같은 bash readline 단축키를 가로챈다.
- 줄 전체 삭제: `Ctrl+C` (현재 입력 버리고 새 프롬프트)
- 줄 처음으로: `Home` 키
- 줄 끝으로: `End` 키
