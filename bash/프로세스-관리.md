# 프로세스 관리

긴 실험을 백그라운드로 돌리기, SSH 세션 끊겨도 계속 실행, 잘못 시작한 프로세스 죽이기. 원격 GPU 서버에서 특히 자주 씀.

---

## 1. 백그라운드 실행 `&`

명령어 끝에 `&` 붙이면 **현재 쉘은 점령 안 하고 뒷단에서 실행**.

```bash
python train.py &
# [1] 12345               ← job ID [1], PID 12345
# 다음 prompt 바로 나옴

# 여러 개 동시에
python eval_a.py &
python eval_b.py &
python eval_c.py &
```

**특징**:
- stdout/stderr는 여전히 터미널에 찍힘 → 로그가 섞임 → 리다이렉트 필수
- 터미널 닫으면 (**SSH 세션 종료 포함**) 죽음 → `nohup` 또는 `tmux` 필요

### stdout/stderr 리다이렉트와 함께

```bash
# 실제 실전 패턴
python train.py > train.log 2>&1 &

# 로그 실시간 보기
tail -f train.log
# Ctrl+C로 tail만 멈춤 (train.py는 계속 돔)
```

## 2. `nohup` — 터미널 끊겨도 계속 실행

**N**o **h**ang**up**. SIGHUP 시그널 무시하고 실행.

```bash
nohup python train.py > train.log 2>&1 &
# [1] 12345
# nohup: ignoring input and appending output to 'nohup.out'

# SSH 끊어도 계속 실행
# 세션 다시 접속하면 tail -f train.log 로 진행 확인
```

**특징**:
- 입력(stdin) 받지 않음 (인터랙티브 프로그램엔 부적합)
- 리다이렉트 안 하면 `nohup.out` 파일에 출력 쌓음
- 터미널 죽어도 실행 유지

### `nohup` + `&` 조합이 표준

```bash
nohup <command> > <logfile> 2>&1 &
```

거의 관용구처럼 외우시면 됩니다.

### 실행 후 PID만 따로 알고 싶으면

```bash
nohup python train.py > train.log 2>&1 &
echo $!         # 방금 백그라운드로 간 프로세스의 PID
echo $! > train.pid      # 파일로 저장 (나중에 kill 할 때 사용)
```

`$!`는 bash 내장 변수: "직전에 백그라운드로 보낸 프로세스의 PID".

## 3. `jobs` — 현재 쉘의 백그라운드 작업 목록

```bash
jobs

# 출력 예:
# [1]+  Running    python train.py > train.log 2>&1 &
# [2]-  Running    python eval.py &
# [3]   Stopped    vim

jobs -l         # PID 포함
jobs -p         # PID만
```

- `[1]`, `[2]`: job ID
- `+`: 가장 최근 job (기본 대상)
- `-`: 두 번째 최근
- `Running`/`Stopped`/`Done`

**주의**: `jobs`는 **현재 쉘 세션** 안의 작업만 보여줌. 다른 터미널에서 띄운 건 안 보임 → `ps`로.

## 4. 포그라운드 ↔ 백그라운드 전환 — `fg`, `bg`

### 실행 중 명령을 잠깐 멈춰서 백그라운드로 보내기

```bash
python long_job.py
# ... 실행 중
# Ctrl+Z 누르면 → 일시정지
# [1]+  Stopped    python long_job.py

bg              # 백그라운드에서 재개 (Stopped → Running)
# [1]+ python long_job.py &

# 또는
bg %1           # job ID 1 명시
```

### 백그라운드 작업을 포그라운드로

```bash
fg              # 가장 최근 백그라운드 작업을 전면으로
fg %1           # 특정 job ID
fg %python      # 이름으로 매칭
```

### 자주 쓰는 시나리오

```bash
# 실수로 python train.py 를 & 없이 시작했을 때
python train.py
# Ctrl+Z
bg
disown          # 쉘에서 분리 → 터미널 닫아도 살아남음 (nohup 효과)
```

---

## 5. `disown` — 쉘에서 프로세스 떼어내기

이미 `&`로 백그라운드 돌리고 있던 걸 **`nohup` 없이 시작했는데 SSH 끊기면 죽을까 걱정될 때**:

```bash
jobs                    # 현재 백그라운드 작업 목록
disown %1               # job 1 을 쉘에서 분리
# 이제 터미널 닫혀도 계속 실행됨
disown -a               # 전체 disown
```

`nohup`을 애초에 안 쓴 상태에서도 나중에 구제 가능. 단, 시작 시점부터 `nohup + &`가 표준.

## 6. `ps` — 프로세스 검색

현재 사용자든 시스템 전체든 프로세스 목록 조회.

```bash
ps                     # 현재 터미널의 프로세스만 (보통 bash, ps 만 보임)
ps aux                 # 시스템 전체 (자주 씀)
ps aux | grep python   # 특정 프로세스 필터

# 다른 옵션 조합
ps -ef                 # BSD 대신 System V 스타일. 비슷한 정보
ps aux | grep $USER    # 내 프로세스만
ps --sort=-%mem        # 메모리 사용량 순 정렬
ps -ef --forest        # 부모-자식 트리로
```

### 자주 쓰는 필드

`ps aux` 출력:
```
USER   PID   %CPU  %MEM  VSZ     RSS     TTY   STAT  START  TIME  COMMAND
sho   12345  98.5   5.2  8.1g    2.3g    ?     Rl    14:02  1:23  python train.py
```

| 필드 | 의미 |
|---|---|
| `PID` | 프로세스 ID (kill 할 때 사용) |
| `%CPU` | CPU 사용률 |
| `%MEM` | 메모리 사용률 |
| `VSZ` | 가상 메모리 |
| `RSS` | 실제 점유 메모리 (KB) |
| `STAT` | 상태 (R=running, S=sleep, D=uninterruptible, Z=zombie) |
| `COMMAND` | 실행 명령 |

### Python 프로세스 찾는 패턴

```bash
ps aux | grep python | grep -v grep     # grep 자기 자신 제외
ps -ef | grep train.py                   # 스크립트명으로
```

### GPU 사용중인 프로세스

```bash
nvidia-smi                               # 맨 아래 Processes 섹션
# 또는
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
```

## 7. `kill` — 프로세스 종료

```bash
kill <PID>              # SIGTERM (기본). 정상 종료 요청
kill -9 <PID>           # SIGKILL. 강제 종료 (정리 안 됨)
kill -l                 # 시그널 목록

# 시그널 이름으로도
kill -SIGTERM 12345
kill -TERM 12345
```

### 주요 시그널

| 시그널 | 숫자 | 설명 |
|:---:|:---:|---|
| `SIGTERM` | 15 | 정상 종료 요청. 프로그램이 cleanup 후 종료 |
| `SIGKILL` | 9 | 강제 종료. 막을 방법 없음. 최후 수단 |
| `SIGINT` | 2 | Ctrl+C와 동일 |
| `SIGHUP` | 1 | 터미널 끊김 신호 (nohup이 무시시키는 것) |
| `SIGSTOP` | 19 | 일시정지 (Ctrl+Z가 보내는 SIGTSTP과 유사) |
| `SIGCONT` | 18 | 재개 |

### 실전

```bash
# 정상 종료 먼저 시도
kill 12345
sleep 5
# 안 죽으면 강제
kill -9 12345
```

### `killall` — 이름으로 죽이기

```bash
killall python                  # python 이름 프로세스 모두
killall -9 python               # 강제
killall -u $USER firefox        # 내 firefox만
```

주의: 너무 광범위해서 실수로 다른 중요 프로세스까지 죽일 위험. **반드시 `ps aux | grep` 으로 먼저 확인**.

### `pkill` — 패턴 매칭으로

```bash
pkill -f "python train.py"      # -f: 전체 커맨드라인에 매칭
pkill -f "python"               # python 들어간 명령 전부 (위험!)
pkill -9 -f "train.py"          # 강제 종료
```

`-f`로 명령어 전체를 보면 더 정확하게 매칭 가능.

### 내 python 프로세스 다 정리하는 관용구

```bash
# 확인 먼저
ps aux | grep python | grep -v grep

# 모두 죽이기
pkill -u $USER -f python

# 강제
pkill -9 -u $USER -f python
```

## 8. `tmux` — 세션 관리 (권장)

`nohup`보다 훨씬 나은 대안. 특히 **긴 실험** + **여러 창을 오가야 할 때**.

```bash
# 새 세션 시작
tmux new -s train

# 세션 안에서 자유롭게 작업
python train.py        # 그냥 &도 nohup도 없이 실행

# 세션에서 나가기 (프로세스는 계속 실행됨)
# Ctrl+b, 그 다음 d

# SSH 끊겼다가 재접속 후
tmux ls                # 세션 목록
tmux attach -t train   # 다시 붙기
```

### 기본 키 바인딩 (Ctrl+b 가 prefix)

| 키 | 동작 |
|:---:|---|
| `Ctrl+b  d` | detach (세션 유지, 빠져나옴) |
| `Ctrl+b  c` | 새 창 (window) |
| `Ctrl+b  n` / `p` | 다음/이전 창 |
| `Ctrl+b  %` | 세로 분할 |
| `Ctrl+b  "` | 가로 분할 |
| `Ctrl+b  방향키` | pane 이동 |
| `Ctrl+b  [` | 스크롤 모드 진입 (q로 빠져나옴) |

### nohup 대신 tmux 권장 이유

- 터미널 끊겨도 유지 (같음)
- 출력을 직접 볼 수 있음 (nohup은 로그 파일 tail 필요)
- 여러 창 분할 가능 (train 실행 + tail log + nvidia-smi 동시)
- 세션 이름으로 관리

### 자주 쓰는 패턴

```bash
# 실험 세션
tmux new -s exp1
python train.py
# Ctrl+b, d

# 모니터링 세션
tmux new -s mon
watch -n 1 nvidia-smi
# Ctrl+b, d

# 세션 전환
tmux ls
# exp1: ...
# mon:  ...
tmux attach -t exp1
```

### 세션 종료

```bash
tmux kill-session -t exp1
tmux kill-server              # 모든 tmux 세션 정리
```

## 9. 실전 패턴

### 패턴 A: 긴 학습을 안전하게 백그라운드로

```bash
# 방법 1: nohup
nohup python train.py --epochs 100 > train.log 2>&1 &
echo $! > train.pid
tail -f train.log

# 방법 2: tmux (권장)
tmux new -s train
python train.py --epochs 100
# Ctrl+b, d
tmux attach -t train
```

### 패턴 B: 여러 실험 병렬 실행

```bash
# GPU 할당 명시해서 동시에
CUDA_VISIBLE_DEVICES=0 python train.py --lr 1e-3 > log_lr3.txt 2>&1 &
CUDA_VISIBLE_DEVICES=1 python train.py --lr 1e-4 > log_lr4.txt 2>&1 &
CUDA_VISIBLE_DEVICES=2 python train.py --lr 1e-5 > log_lr5.txt 2>&1 &

# 모두 끝나기 기다리기
wait
echo "all done"
```

`wait`은 현재 쉘의 모든 백그라운드 작업 완료 대기.

### 패턴 C: 중간 에러 발생 시 정리

```bash
#!/bin/bash
set -euo pipefail

# 백그라운드 프로세스 PID 모으기
pids=()

python service_a.py &
pids+=($!)

python service_b.py &
pids+=($!)

# 종료 시그널 받으면 자식들도 정리
trap 'kill "${pids[@]}" 2>/dev/null' EXIT

# 메인 작업
python main.py
```

`trap`은 쉘 이벤트(EXIT, INT 등)에 핸들러 등록. 스크립트 종료 시 자동 정리 패턴.

### 패턴 D: 특정 프로세스 다 끝나고 다음 실행

```bash
# 이전 python 작업 끝날 때까지 대기
while pgrep -u $USER -f "python train.py" > /dev/null; do
    echo "이전 작업 진행중, 대기..."
    sleep 60
done

echo "이전 작업 종료됨, 새 작업 시작"
python new_train.py
```

### 패턴 E: 메모리 많이 먹는 프로세스 찾기

```bash
# RSS 순으로 상위 10개
ps aux --sort=-rss | head -11        # +1 for header

# 내 프로세스만
ps -u $USER --sort=-rss | head -11
```

## 10. 실수하기 쉬운 지점

### 실수 1: `&` 안 써서 터미널 점령당함

```bash
nohup python train.py > log.txt 2>&1    # ❌ & 빠지면 포그라운드 그대로
# 터미널 점유됨, Ctrl+C 안 누르면 다른 작업 못 함
```

**관용구**: `nohup ... 2>&1 &` — 끝에 `&` 까먹지 말기.

### 실수 2: `&` 쓰고 터미널 닫음 → 죽음

```bash
python train.py &
# SSH 창 닫기
# → SIGHUP 받고 프로세스 죽음
```

해결: `nohup`을 같이 쓰거나 `tmux`.

### 실수 3: `kill -9` 부터 시작

`SIGKILL(-9)`은 **무조건 강제 종료** → 프로세스가 정리할 기회 없음. DB connection 남음, 파일 락 남음, GPU 메모리 leak.

**순서**: `kill <PID>` (SIGTERM) → 안 죽으면 5~10초 기다림 → `kill -9 <PID>`.

### 실수 4: `ps aux | grep pattern` 이 자기 자신까지 매칭

```bash
ps aux | grep python
# 결과 중에 grep 자기 자신도 들어감
```

해결:
```bash
ps aux | grep python | grep -v grep
# 또는
pgrep python      # 전용 명령
```

### 실수 5: 잘못된 PID에 `kill -9`

절대로 `pkill -9 -f "py"` 같이 광범위한 패턴 쓰지 않기. 시스템 프로세스까지 죽일 수 있음.

**안전 패턴**:
```bash
# 1. 먼저 확인
ps aux | grep "train.py" | grep -v grep

# 2. PID 확인 후 개별 kill
kill 12345

# 3. 안 죽으면 강제
kill -9 12345
```

### 실수 6: `nvidia-smi` GPU 메모리 안 빠짐

GPU 프로세스를 `-9`로 죽이면 메모리가 안 풀릴 수 있음 (ghost process). 해결:

```bash
# 해당 GPU 사용중인 프로세스 PID 찾기
nvidia-smi --query-compute-apps=pid --format=csv,noheader
# 또는
fuser -v /dev/nvidia*

# 보이는 PID 모두 kill
kill -9 <pid_list>
```

그래도 안 풀리면 재부팅이나 드라이버 리셋.

## 11. 한 줄 요약 치트시트

```bash
# 백그라운드 + SSH 안전
nohup python train.py > train.log 2>&1 &
tail -f train.log

# 더 좋은 방법: tmux
tmux new -s train
# ... 작업 ...
# Ctrl+b, d (detach)
tmux attach -t train

# 프로세스 확인
ps aux | grep python | grep -v grep
pgrep -u $USER -f "train.py"

# 종료
kill <PID>             # 정상
kill -9 <PID>          # 강제 (최후)
pkill -f "train.py"    # 이름 매칭

# 마지막 백그라운드 PID
echo $!

# 모든 백그라운드 완료 대기
wait
```
