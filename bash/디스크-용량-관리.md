# 디스크 용량 관리 워크플로우

디스크 꽉 찼을 때 **체크 → 범인 찾기 → 이동/삭제** 순서로 보는 실전 치트시트.

> 📚 관련 상세 문서:
> - 전체 모니터링 명령: [자원-모니터링.md](자원-모니터링.md)
> - cp / mv / rsync 상세: [파일-복사-이동.md](파일-복사-이동.md)
> - 캐시 위치 옮기기: [캐시-디스크-관리.md](캐시-디스크-관리.md)

## 1단계: 전체 상황 파악 (어느 디스크가 차있나)

```bash
# 마운트된 모든 디스크 용량
df -h

# 출력 예시:
# Filesystem      Size  Used Avail Use% Mounted on
# /dev/sda1       500G  480G   20G  96% /home     ← 여기가 문제
# /dev/sdb1       2.0T  800G  1.2T  40% /data     ← 여유 있음

# 특정 경로가 어느 디스크에 속하는지
df -h ~
df -h /data

# inode 부족 확인 (용량 남았는데 "No space left" 에러 뜰 때)
df -i
```

## 2단계: 용량 먹는 범인 찾기

### 홈 디렉토리에서 큰 폴더 찾기

```bash
# 홈 아래 바로 밑 폴더별 크기 (가장 자주 씀)
du -sh ~/*
du -sh ~/.*  2>/dev/null              # 숨김 폴더도

# 크기순 정렬 (큰 것부터)
du -sh ~/* 2>/dev/null | sort -rh | head -10

# 깊이 2단계까지 + 크기순
du -h --max-depth=2 ~ 2>/dev/null | sort -rh | head -20
```

### 의심 경로 빠르게 점검

```bash
# 자주 용량 터지는 주범들
du -sh ~/.cache                        # 각종 캐시
du -sh ~/.cache/torch                  # PyTorch 모델/JIT
du -sh ~/.cache/huggingface            # HF 모델 (수십 GB 가기 쉬움)
du -sh ~/.cache/torch_extensions       # JIT 컴파일 결과
du -sh ~/.cache/pip                    # pip 캐시
du -sh ~/miniconda3                    # conda 전체
du -sh ~/miniconda3/envs/*             # conda 환경별
du -sh ~/miniconda3/pkgs               # conda 패키지 캐시
du -sh ~/.local/share/Trash            # 휴지통
du -sh ~/Downloads                     # 다운로드 폴더
```

### 큰 파일 찾기

```bash
# 1GB 이상 파일 찾기
find ~ -type f -size +1G 2>/dev/null

# 크기순으로 정렬해서 보기
find ~ -type f -size +500M 2>/dev/null -exec du -h {} \; | sort -rh | head -20

# 특정 확장자만 (체크포인트, 모델 파일)
find ~ -type f \( -name "*.pt" -o -name "*.pth" -o -name "*.ckpt" -o -name "*.bin" \) -exec du -h {} \; | sort -rh | head -20

# 오래된 파일 찾기 (30일 이상 안 쓴 것)
find ~/Downloads -type f -mtime +30 -exec du -h {} \; | sort -rh
```

### 대화형 탐색기 (강추) ⭐

`ncdu`는 파일 탐색기처럼 폴더 드나들면서 용량 볼 수 있음. 훨씬 빠르고 직관적.

```bash
sudo apt install ncdu

ncdu ~                                 # 홈 디렉토리 탐색
ncdu /                                 # 전체 시스템 (느림, 마운트 제외는 -x)
ncdu -x /                              # 다른 파일시스템 제외

# 조작법: 방향키 이동, Enter로 진입, d로 삭제, q로 종료
```

## 3단계: 이동 (다른 디스크로)

### 옮기기 전 확인

```bash
# 대상 디스크에 공간 있는지
df -h /data

# 옮길 폴더 크기 먼저 확인 (시간 예상용)
du -sh ~/datasets
```

### mv — 같은 파일시스템이면 빠름

```bash
# 같은 디스크(파일시스템) 내면 즉시 완료
mv ~/datasets /home/me/archive/

# 다른 디스크로 옮길 때는 실제로 복사 후 삭제 → 느림
mv ~/datasets /data/datasets           # 시간 오래 걸리고, 중단되면 복구 어려움
```

### rsync — 다른 디스크로 옮길 때 추천 ⭐

진행률 표시 + 중단되면 이어하기 가능.

```bash
# 1. 복사 (진행률 표시)
rsync -av --progress ~/datasets/ /data/datasets/

# 2. 잘 복사됐는지 크기 비교
du -sh ~/datasets /data/datasets

# 3. 원본 삭제
rm -rf ~/datasets

# 4. 필요하면 심볼릭 링크로 기존 경로 유지
ln -s /data/datasets ~/datasets
```

> ⚠️ `rsync -av` 끝의 `/` 유무로 동작이 달라짐:
> - `src/ dst/` → src 안의 **내용물**이 dst 안으로
> - `src  dst/` → src **폴더째**로 dst 안에 들어감

### 대용량 체크포인트/모델 옮기기

```bash
# 체크포인트를 데이터 디스크로
rsync -av --progress ~/checkpoints/ /data/checkpoints/

# 복사 검증 (파일 개수, 크기 같은지)
du -sh ~/checkpoints /data/checkpoints
find ~/checkpoints -type f | wc -l
find /data/checkpoints -type f | wc -l

# 원본 삭제 + 링크
rm -rf ~/checkpoints
ln -s /data/checkpoints ~/checkpoints
```

## 4단계: 삭제 (안 쓰는 것 정리)

### 안전 순서: 캐시 → 다운로드 → 중복 → 오래된 것

```bash
# ── 캐시 정리 (가장 안전, 효과 큼) ──
pip cache purge                        # pip 캐시
conda clean --all                      # conda 캐시 (수 GB 확보 가능)
rm -rf ~/.cache/torch_extensions/      # JIT 컴파일 캐시 (재빌드됨, OK)

# ── 휴지통 비우기 ──
rm -rf ~/.local/share/Trash/*

# ── 로그 정리 ──
sudo journalctl --vacuum-size=100M    # 시스템 로그 100MB로 제한
sudo journalctl --vacuum-time=7d      # 7일 이전 로그 삭제

# ── apt 캐시 ──
sudo apt clean                         # 다운로드된 .deb 파일 삭제
sudo apt autoremove                    # 불필요한 의존성 패키지 제거
```

### 위험한 삭제 전 확인 습관

```bash
# 1. 먼저 어떤 게 지워질지 확인 (ls로)
ls ~/old_experiments/

# 2. 크기 확인
du -sh ~/old_experiments/

# 3. 정말 지울지 한 번 더 (ls로 파일명 확인)
ls ~/old_experiments/*.pt

# 4. 삭제
rm -rf ~/old_experiments/

# ── 더 안전한 방법: 일단 다른 디스크로 옮겨두기 ──
mv ~/old_experiments /data/_to_delete/
# 며칠 쓰면서 이상 없으면 나중에 삭제
```

> ⚠️ `rm -rf`는 되돌릴 수 없음. 특히 `rm -rf $VAR/` 형태에서 `$VAR`가 비어있으면 `rm -rf /`가 되어 대참사. 변수 쓸 때는 `rm -rf "${VAR:?}/..."` 형태로 빈 값 체크.

### 중복/큰 파일 골라 삭제

```bash
# 1GB 이상 파일 목록 뽑아서 확인 후 삭제
find ~ -type f -size +1G 2>/dev/null > big_files.txt
cat big_files.txt                      # 내용 확인
# 필요한 것만 골라 xargs로 삭제
# cat big_files.txt | xargs rm         # ← 전체 삭제 (주의!)
```

## 5단계: 검증

```bash
# 용량 확보됐는지
df -h ~
df -h /data

# 심볼릭 링크로 연결했으면 정상 작동하는지
ls -la ~/datasets                      # 링크 화살표 표시 확인
ls ~/datasets/                         # 실제 파일 접근되는지
```

## 상황별 빠른 대응

### "No space left on device" 지금 당장 뜸

```bash
# 즉시 확보 (보통 10~50GB)
pip cache purge
conda clean --all -y
rm -rf ~/.cache/torch_extensions/
rm -rf /tmp/*  2>/dev/null
sudo journalctl --vacuum-size=100M
```

### 학습 중 체크포인트 쌓여서 터짐

```bash
# 오래된 체크포인트만 삭제 (최근 3개는 유지)
ls -t ~/checkpoints/*.pt | tail -n +4 | xargs rm -f
```

### HuggingFace 모델 너무 많이 받음

```bash
pip install -U "huggingface_hub[cli]"
huggingface-cli delete-cache           # 대화형으로 선택 삭제
# 또는 위치 변경: export HF_HOME=/data/cache/huggingface
```

## 요약 치트시트

| 목적 | 명령 |
|------|------|
| 디스크 상황 | `df -h` |
| 폴더 크기 | `du -sh ~/*` |
| 큰 순서 TOP 10 | `du -sh ~/* \| sort -rh \| head -10` |
| 대화형 탐색 | `ncdu ~` |
| 큰 파일 찾기 | `find ~ -size +1G 2>/dev/null` |
| 안전한 이동 | `rsync -av --progress SRC/ DST/` |
| 캐시 정리 | `pip cache purge && conda clean --all` |
| 심볼릭 링크 | `ln -s /data/폴더 ~/폴더` |
