# CUDA 버전 관리 & 트러블슈팅

## 버전 확인

```bash
# 드라이버가 지원하는 최대 CUDA 버전
nvidia-smi
# 우측 상단의 "CUDA Version: 12.6" → 이 버전까지 사용 가능

# 현재 활성화된 nvcc (컴파일러) 버전
nvcc --version

# 설치된 CUDA 툴킷 목록
ls /usr/local/cuda*

# PyTorch가 사용하는 CUDA 버전
python -c "import torch; print(torch.version.cuda)"

# PyTorch 설치
pip3 install torch torchvision --index-url https://download.pytorch.org/whl/cu128
```



## 핵심 개념: 드라이버 vs 툴킷

| 구분 | 설명 | 확인 명령 |
|------|------|-----------|
| **NVIDIA 드라이버** | GPU 하드웨어와 통신. WSL에서는 Windows 드라이버 사용 | `nvidia-smi` |
| **CUDA 툴킷** | nvcc 컴파일러, 라이브러리. 여러 버전 공존 가능 | `nvcc --version` |
| **PyTorch CUDA** | PyTorch가 빌드된 CUDA 버전 | `torch.version.cuda` |

> 💡 드라이버의 CUDA 버전 ≥ 툴킷 버전이면 OK  
> 예: 드라이버 12.6, 툴킷 12.4 → ✅ 호환

## 패키지 관리

```bash

# 1. runfile 다운로드
cd ~/Downloads  # 또는 적당한 임시 디렉토리
wget https://developer.download.nvidia.com/compute/cuda/12.8.0/local_installers/cuda_12.8.0_570.86.10_linux.run

# 2. 실행
sudo sh cuda_12.8.0_570.86.10_linux.run --toolkit --toolkitpath=/usr/local/cuda-12.8 --silent --override

옵션 의미:

--toolkit: 툴킷만 설치 (드라이버는 제외 — 기존 드라이버 유지)
--toolkitpath=/usr/local/cuda-12.8: 설치 경로 지정
--silent: 대화형 프롬프트 없이 설치
--override: GCC 버전 체크 등 일부 호환성 검사 무시 (RHEL 9.2처럼 GCC 버전이 엄격한 환경에서 필요할 수 있음)

중요: --driver 옵션은 절대 넣지 마세요. 기존 NVIDIA 드라이버를 덮어쓰면 다른 CUDA 환경들이 깨질 수 있습니다. 드라이버는 최신 버전 하나만 있으면 CUDA 11.8/12.x 모두 지원합니다 (하위 호환).
대화형으로 하시려면 --silent 빼고 실행하면 텍스트 메뉴가 뜹니다. 거기서 Driver 체크를 반드시 해제하고 Toolkit만 선택, Options → Toolkit Options → Change Toolkit Install Path에서 /usr/local/cuda-12.8 지정하시면 됩니다.


# 3. 설치 확인
bashls /usr/local/cuda-12.8/bin/nvcc
/usr/local/cuda-12.8/bin/nvcc --version

4. 환경 변수 설정 (필요할 때만 활성화)
기본 /usr/local/cuda 심볼릭 링크는 건드리지 마세요. 기존 CUDA 11.8 환경을 쓰는 프로젝트들이 깨집니다. 대신 필요할 때만 셸에서 활성화하는 방식을 추천합니다.
예를 들어 ~/bin/cuda128-env.sh 같은 파일을 만들어서:
bashexport CUDA_HOME=/usr/local/cuda-12.8
export PATH=$CUDA_HOME/bin:$PATH
export LD_LIBRARY_PATH=$CUDA_HOME/lib64:$LD_LIBRARY_PATH


# 패키지 설치
conda install numpy
conda install -c nvidia cuda-toolkit=12.6    # nvidia 채널에서 설치
conda install -c conda-forge gcc_linux-64=12  # conda-forge 채널에서 설치

# pip로 설치 (conda에 없는 패키지)
pip install -r requirements.txt
pip install gsplat==1.5.3

# 설치된 패키지 목록
conda list
pip list

# 특정 패키지 버전 확인
python -c "import torch; print(torch.__version__)"
python -c "import torch; print(torch.cuda.is_available())"
```

## CUDA 설치 방식: conda vs runfile

CUDA 툴킷을 설치하는 두 가지 주요 방식과 차이점 정리.

### 두 가지 설치 명령 예시

```bash
# 방식 1: conda
conda install -c nvidia cuda-toolkit=12.6

# 방식 2: runfile (NVIDIA 공식 설치 스크립트)
wget https://developer.download.nvidia.com/compute/cuda/12.8.0/local_installers/cuda_12.8.0_570.86.10_linux.run
sudo sh cuda_12.8.0_570.86.10_linux.run \
    --toolkit \
    --toolkitpath=/usr/local/cuda-12.8 \
    --silent --override
```

### 핵심 비교

| 항목 | conda install | runfile |
|---|---|---|
| 설치 위치 | `$CONDA_PREFIX/` | `/usr/local/cuda-X.Y` (지정 경로) |
| 권한 | sudo 불필요 | sudo 필요 (시스템 경로 기준) |
| 격리 | conda 환경별 완전 격리 | 시스템 전역, 환경 변수로 전환 |
| 범위 | 환경 활성화 시에만 유효 | 시스템 전체 |
| 완전성 | 일부 구성요소 누락 가능 | 완전한 풀 툴킷 |
| 드라이버 설치 | 안 함 | `--toolkit` 플래그 시 안 함 |
| 제거 | `conda remove` / 환경 삭제 | uninstaller 스크립트 |

### 실질적 차이

**1. 완전성**

conda의 `cuda-toolkit` 패키지는 runfile에 포함된 전부를 제공하지 않을 수 있다.
일부 헤더, 샘플, 특정 라이브러리(`libcuda.so` 스텁 등)가 빠지거나 경로가 달라서
소스 빌드(gsplat, droid_backends, MegaSAM의 CUDA 커널 등)에서 문제가 생길 수 있다.
nvcc로 CUDA 커널을 직접 빌드하는 경우 runfile 방식이 더 안정적이다.

**2. 격리 vs 공유**

- conda: 환경별 격리가 완벽. `conda activate`로 자동 전환. 환경 변수 수동 관리 불필요.
- runfile: 시스템 전역 설치. `CUDA_HOME`, `PATH`, `LD_LIBRARY_PATH`를 수동 전환해야 함.

**3. 버전 선택**

- conda: `nvidia` 채널이 제공하는 주요 버전만 (12.6, 12.4, 12.1, 11.8 등).
- runfile: NVIDIA 아카이브의 모든 패치 버전 지정 가능 (12.8.0, 12.8.1 등).

**4. 권한**

sudo 없는 환경(예: 회사 슈퍼컴 RHEL 9.2)에서는 conda가 거의 유일한 선택.
runfile도 홈 디렉토리에 설치하면 sudo 없이 가능하지만 conda 쪽이 편리.

### 권장 순서

소스 CUDA 빌드가 필요한 프로젝트(gsplat, Depth Anything V3 등)에서는 다음 순서로 시도:

1. **먼저 conda 방식으로 시도** (빠르고 간단)

   ```bash
   conda create -n dav3 python=3.12 -y
   conda activate dav3
   conda install -c nvidia/label/cuda-12.6.0 cuda-toolkit -y
   pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
   pip install --no-build-isolation \
       git+https://github.com/nerfstudio-project/gsplat.git@<commit>
   ```

2. **gsplat 빌드에서 헤더 관련 에러가 나면 runfile로 전환**

   conda 환경은 그대로 유지하고, 빌드 시에만 `CUDA_HOME`을 덮어쓴다:

   ```bash
   export CUDA_HOME=/usr/local/cuda-12.8
   export PATH=$CUDA_HOME/bin:$PATH
   export LD_LIBRARY_PATH=$CUDA_HOME/lib64:$LD_LIBRARY_PATH
   ```

### runfile 설치 시 주의사항

- **`--driver` 옵션은 절대 사용 금지**. 기존 NVIDIA 드라이버를 덮어쓰면 다른 CUDA 환경들이 깨진다.
  드라이버는 최신 하나만 있으면 CUDA 11.8 / 12.x 모두 하위 호환된다.
- **`/usr/local/cuda` 심볼릭 링크는 건드리지 말 것**. 기존 환경(예: CUDA 11.8 기반 MegaSAM)이 깨진다.
  대신 버전별 경로(`/usr/local/cuda-12.8`)를 직접 환경 변수로 지정.
- **드라이버 호환성 확인**: CUDA 12.8은 NVIDIA 드라이버 570.26 이상 필요.
  `nvidia-smi`로 먼저 확인.
- **GCC 버전**: CUDA 12.8은 GCC 13까지 지원. RHEL 9.2(기본 GCC 11)는 문제없음.

### 자주 겪는 에러

**`RuntimeError: The detected CUDA version (X) mismatches the version that was used to compile PyTorch (Y)`**

nvcc의 CUDA 버전과 PyTorch가 링크된 CUDA 버전이 다를 때 발생.
해결책: 둘 중 하나를 맞춘다.

```bash
# 현재 상태 확인
python -c "import torch; print(torch.__version__, torch.version.cuda)"
nvcc --version
echo $CUDA_HOME
which nvcc
```

- PyTorch를 nvcc 버전에 맞춰 재설치, 또는
- nvcc(CUDA 툴킷)를 PyTorch 버전에 맞춰 설치/전환.


## CUDA 경로 전환

여러 CUDA 버전이 설치되어 있을 때 원하는 버전으로 전환:

```bash
# CUDA 12.4 사용
export PATH=/usr/local/cuda-12.4/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-12.4/lib64:$LD_LIBRARY_PATH

# CUDA 11.8로 돌아가기
export PATH=/usr/local/cuda-11.8/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-11.8/lib64:$LD_LIBRARY_PATH
```

## 시스템 기본 CUDA 버전 변경 (영구 설정)

터미널을 열 때마다 원하는 CUDA가 기본으로 잡히게 하려면 `~/.bashrc`에 추가:

```bash
# ~/.bashrc 맨 아래에 추가
export PATH=/usr/local/cuda-12.4/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-12.4/lib64:$LD_LIBRARY_PATH
```

```bash
source ~/.bashrc
nvcc --version   # 12.4 확인
```

> ⚠️ 기존에 다른 CUDA 경로가 `~/.bashrc`에 있다면 먼저 제거할 것

## conda 가상환경별 CUDA 버전 설정

환경마다 다른 CUDA 버전을 쓰고 싶을 때, `activate.d` / `deactivate.d` 스크립트를 사용:

```bash
# 1. 환경 생성 & 활성화
conda create -n myenv python=3.9 -y
conda activate myenv

# 2. 디렉토리 생성
mkdir -p $CONDA_PREFIX/etc/conda/activate.d
mkdir -p $CONDA_PREFIX/etc/conda/deactivate.d

# 3. 활성화 시 CUDA 12.4로 전환
cat > $CONDA_PREFIX/etc/conda/activate.d/cuda.sh << 'EOF'
export ORIGINAL_PATH=$PATH
export ORIGINAL_LD_LIBRARY_PATH=$LD_LIBRARY_PATH
export PATH=/usr/local/cuda-12.4/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-12.4/lib64:$LD_LIBRARY_PATH
EOF

# 4. 비활성화 시 원래대로 복원
cat > $CONDA_PREFIX/etc/conda/deactivate.d/cuda.sh << 'EOF'
export PATH=$ORIGINAL_PATH
export LD_LIBRARY_PATH=$ORIGINAL_LD_LIBRARY_PATH
unset ORIGINAL_PATH
unset ORIGINAL_LD_LIBRARY_PATH
EOF
```

결과: `conda activate myenv` → CUDA 12.4 / `conda deactivate` → 시스템 기본(예: 11.8)으로 복원

### 사용 가능 여부 판단 기준

| nvidia-smi CUDA Version | /usr/local에 설치된 툴킷 | 사용 가능? |
|--------------------------|--------------------------|------------|
| 12.4 | cuda-11.8 | ✅ 11.8 ≤ 12.4 |
| 12.4 | cuda-12.4 | ✅ 12.4 = 12.4 |
| 12.4 | cuda-12.6 | ❌ 12.6 > 12.4 (드라이버 업그레이드 필요) |

> 💡 `nvidia-smi`의 CUDA Version = 드라이버가 지원하는 **상한선**. 이보다 높은 툴킷은 드라이버를 먼저 업그레이드해야 사용 가능.

## NVIDIA 드라이버 업그레이드

더 높은 CUDA 툴킷을 사용하려면 드라이버를 업그레이드해야 한다.

### 드라이버 ↔ CUDA 버전 매핑

| 드라이버 시리즈 | 지원 최대 CUDA | 비고 |
|----------------|---------------|------|
| 535.x | 12.2 | |
| 550.x | 12.4 | |
| 560.x | 12.6 | |
| 570.x | 12.8 | |

### 네이티브 Linux 업그레이드

```bash
# 기존 드라이버 제거 없이 바로 설치 가능 (자동 교체됨)
sudo apt-get update
sudo apt-get install nvidia-driver-570 -y

# 재부팅 필수 (커널 모듈 교체이므로 생략 불가)
sudo reboot

# 확인
nvidia-smi   # CUDA Version: 12.8 나오면 성공
```

> ⚠️ 재부팅은 필수다. GPU 드라이버는 커널 모듈이라 새로 로드해야 한다.
> `sudo rmmod nvidia` 후 재로드하는 방법도 있지만, GPU를 사용하는 프로세스가 있으면 실패하므로 reboot이 안전하다.

### WSL2의 경우

WSL2에서는 Linux 안에서 드라이버 설치가 불가하다. **Windows 쪽 드라이버**를 업그레이드해야 한다:

1. [NVIDIA 드라이버 다운로드](https://www.nvidia.com/download/index.aspx)에서 GPU에 맞는 최신 드라이버(570+) 다운로드
2. Windows에서 설치 후 재부팅
3. WSL2 터미널에서 `nvidia-smi`로 확인

## GPU 선택 (CUDA_VISIBLE_DEVICES)

```bash
# GPU 0번만 사용
export CUDA_VISIBLE_DEVICES=0

# GPU 1번만 사용
export CUDA_VISIBLE_DEVICES=1

# 둘 다 사용
export CUDA_VISIBLE_DEVICES=0,1

# GPU 없이 CPU만 사용
export CUDA_VISIBLE_DEVICES=""
```

## TORCH_CUDA_ARCH_LIST

JIT 컴파일 시 어떤 GPU 아키텍처를 타겟할지 지정:

```bash
# RTX 3090 / 3080 / 3070 (Ampere)
export TORCH_CUDA_ARCH_LIST="8.6"

# RTX 4090 (Ada Lovelace)
export TORCH_CUDA_ARCH_LIST="8.9"

# H100 (Hopper)
export TORCH_CUDA_ARCH_LIST="9.0"

# 여러 아키텍처 동시 지정
export TORCH_CUDA_ARCH_LIST="8.6;9.0"
```

### 주요 GPU → compute capability

| GPU | Compute Capability |
|-----|--------------------|
| GTX 1080 Ti / TITAN Xp | 6.1 |
| RTX 2080 Ti | 7.5 |
| RTX 3070 / 3080 / 3090 | 8.6 |
| RTX 4070 / 4080 / 4090 | 8.9 |
| A100 | 8.0 |
| H100 | 9.0 |

## 자주 만나는 에러

### `cooperative_groups::labeled_partition` 에러

```
error: namespace "cooperative_groups" has no member "labeled_partition"
```

**원인**: CUDA 11.x로 컴파일하는데, 코드가 CUDA 12+ API를 사용  
**해결**: CUDA 12.x 경로로 전환 후 재컴파일

```bash
export PATH=/usr/local/cuda-12.4/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-12.4/lib64:$LD_LIBRARY_PATH
rm -rf ~/.cache/torch_extensions/
```

### `sm_XX is not compatible` 경고

```
NVIDIA TITAN Xp with CUDA capability sm_61 is not compatible
```

**원인**: 설치된 PyTorch가 해당 GPU 아키텍처를 지원하지 않음  
**해결**: `CUDA_VISIBLE_DEVICES`로 호환되는 GPU만 사용하거나, `TORCH_CUDA_ARCH_LIST`로 호환 GPU만 타겟

### JIT 빌드 캐시 문제

컴파일이 한번 실패하면 깨진 캐시가 남아서 계속 실패할 수 있음:

```bash
# JIT 컴파일 캐시 전체 삭제
rm -rf ~/.cache/torch_extensions/
```
